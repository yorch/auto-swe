## Overview

The dashboard is a Next.js App Router application. The `packages/web/src/app/` tree holds 58 `page.tsx` files, one root layout, a `studio` layout, a `govern` layout plus 16 per-page `govern` layouts, and a `health` route handler. Navigation is not derived from the file tree: a single hand-written table in `lib/navigation.ts` defines the sidebar, TopBar titles and breadcrumb sections, so a page's label, title and heading come from the same string.

## Route tree

Top-level segments under `app/` are `agent-runs`, `connections`, `docs`, `epics`, `govern`, `health`, `lessons`, `login`, `oauth`, `pull-requests`, `reset-password`, `runs`, `settings`, `start`, `studio`, `tickets` and `workflows`, plus the root `page.tsx` (Home), `error.tsx`, `global-error.tsx` and `not-found.tsx`. Dynamic segments appear for `docs/[slug]`, `epics/[workflowId]`, `runs/[id]` and `workflows/[id]`, and for the detail pages under `govern` and `workflows/library`.

The `workflows` segment has two sides. `workflows/page.tsx` is the request list (labelled "Requests" in the sidebar), `workflows/[id]` is a single request, and `workflows/library` lists workflow templates with `[id]` detail pages plus `analytics`, `diff` and `runs` sub-pages per template. `epics` holds a list and a `[workflowId]` detail page and is attributed to the Requests entry.

`studio` has 7 pages: `agents/library`, `bundles`, `github-installations`, `integrations`, `mcp`, `models` and `skills`. `govern` has 27 pages, including detail routes for `evals/datasets/[id]`, `evals/runs/[id]`, `organizations/[orgId]`, `slack-channels/[id]` and `teams/[id]`, and a nested `policies/decisions` page.

Three routes sit outside the authenticated shell's normal flow: `login`, `reset-password` and `oauth/consent`. The `health` segment is a route handler returning `{ status: 'ok' }` for the container health check ([health/route.ts#L5-L7](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/health/route.ts#L5-L7)). A legacy URL is kept as a redirect: `govern/budget-alerts` calls `redirect('/govern/organizations?alerting=1')` because budget alerts became an "Alerting only" filter on Organizations ([budget-alerts/page.tsx#L1-L6](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/govern/budget-alerts/page.tsx#L1-L6)).

## Root layout

`RootLayout` wraps every page in `Providers` and `AppShell` ([layout.tsx#L34-L64](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/layout.tsx#L34-L64)). It loads the Inter and IBM Plex Mono fonts and sets the title template `%s · auto·swe` ([layout.tsx#L9-L26](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/layout.tsx#L9-L26)).

The layout exports `dynamic = 'force-dynamic'` ([layout.tsx#L32](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/layout.tsx#L32)). It serialises `publicApiUrl()` and `temporalUiUrl()` into `AppConfigScript`, escaping `<`, `>` and `&`, so the values come from the running container's environment rather than being baked in at build time ([layout.tsx#L28-L41](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/layout.tsx#L28-L41)).

## Role guards

Access control by route is expressed as layouts that wrap children in `RoleLayout` with an `allowed` role list. `studio/layout.tsx` allows only `ADMIN` ([studio/layout.tsx#L4-L6](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/studio/layout.tsx#L4-L6)). `govern/layout.tsx` admits `ENGINEER`, `LEAD` and `ADMIN` ([govern/layout.tsx#L4-L6](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/govern/layout.tsx#L4-L6)), so every Govern page is open to the three roles unless a nested layout narrows it.

Nested layouts narrow it per page. `users`, `api-tokens`, `audit`, `config-grants`, `evals`, `lessons`, `policies`, `scanner`, `security`, `sessions`, `slack-channels` and `workflow-defaults` allow `ADMIN` only ([users/layout.tsx#L4-L6](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/govern/users/layout.tsx#L4-L6)). `baselines`, `organizations` and `platform-settings` allow `LEAD` and `ADMIN` ([baselines/layout.tsx#L5](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/govern/baselines/layout.tsx#L5)). `usage` is gated on holding a usage scope rather than on a role: its layout calls `requireUsageScope` ([usage/layout.tsx#L5-L10](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/govern/usage/layout.tsx#L5-L10)). Pages without a nested layout, such as `teams`, `analytics`, `approvals` and `schedules`, inherit the three-role Govern guard.

The authentication check itself happens before layouts run, in the proxy: it lets `/login`, `/api`, `/reset-password`, `/health` and `/oauth/consent` through and redirects every other path without a session cookie to `/login` ([proxy.ts#L14-L69](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/proxy.ts#L14-L69)).

## Navigation groups

`NAV_GROUPS` defines four groups ([navigation.ts#L44-L257](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L44-L257)). Each `NavItem` carries `href`, `label`, `icon`, `minRole`, and optionally `section`, `alsoActiveFor` and `needsUsageScope` ([navigation.ts#L20-L37](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L20-L37)). The file's comment requires `minRole` to match the route's `RoleLayout` and the gateway's `requiredRole`, since a looser entry bounces users and a stricter one hides usable pages ([navigation.ts#L15-L19](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L15-L19)).

- **Work** (all `ENGINEER`): Home, Requests (`/workflows`, also active for `/epics`), Pull requests, Tickets, All runs, Approvals (`/govern/approvals`), Workflow library and Connections ([navigation.ts#L45-L73](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L45-L73)).
- **Studio** (all `ADMIN`): Agents, Skills, MCP connections, Integrations, GitHub installations, Model configuration and Bundles ([navigation.ts#L74-L96](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L74-L96)).
- **Govern**, split into collapsible sections: Access (Users, Teams, Organizations, Sessions, API tokens), Security (Scanner patterns, Autonomy policies, Autonomy decisions, Security events, Audit log), Spend and insights (Analytics, LLM usage), Configuration (Platform settings, Workflow defaults, Config grants, Schedules, Slack channels) and Knowledge (Lessons, Error baselines, Evals) ([navigation.ts#L97-L249](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L97-L249)).
- **Account**: Settings and Docs, both `ENGINEER` ([navigation.ts#L250-L256](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L250-L256)).

Within Govern the minimum roles vary: Teams, Analytics and Schedules are `ENGINEER`; Organizations, Platform settings and Error baselines are `LEAD`; the rest are `ADMIN`. LLM usage is `ENGINEER` but flagged `needsUsageScope`, so it appears only to someone who holds a usage scope or is an `ADMIN` ([navigation.ts#L179-L188](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L179-L188)). Organizations also owns `/govern/budget-alerts` through `alsoActiveFor` ([navigation.ts#L113-L122](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L113-L122)).

## Navigation helpers

`visibleNavGroups(role, hasUsageScope)` filters each group with `hasRole` against `minRole`, applies the usage-scope rule, and drops groups left empty ([navigation.ts#L265-L277](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L265-L277)). `navSections` buckets a group's items by `section` in first-appearance order, with unsectioned items in a leading block whose label is `null` ([navigation.ts#L283-L295](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L283-L295)).

`activeNavHref` picks the longest-matching `href` or `alsoActiveFor` prefix for a pathname, so `/govern/policies/decisions` highlights itself rather than Autonomy policies ([navigation.ts#L298-L313](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L298-L313)). `isStartWorkPath` identifies `/start`, which the sidebar's persistent button owns rather than a nav item ([navigation.ts#L316-L318](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L316-L318)).

Pages with no sidebar entry get titles from `EXTRA_PAGE_TITLES`: runs (`Run`), `/start`, autonomy decisions, `/epics`, `/docs`, `/lessons` and `/oauth/consent` ([navigation.ts#L324-L332](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L324-L332)). `knownPageTitle` checks those first, then the active nav item, then falls back to `Govern` or `Studio` by prefix, and `pageTitle` substitutes a generic `Page` rather than "Not found" ([navigation.ts#L338-L365](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L338-L365)). `navLabel(href)` returns the label a page must use as its H1 and throws for an href with no nav entry, as the Approvals page relies on ([navigation.ts#L368-L374](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L368-L374), [govern/approvals/page.tsx#L17](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/app/govern/approvals/page.tsx#L17)).

`pageSection` computes the breadcrumb's first segment: Docs reports `Help`, other nav pages report their group label, and `/start`, `/epics` and `/lessons` map to Work, Work and Govern through `EXTRA_PAGE_SECTIONS` ([navigation.ts#L377-L410](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/web/src/lib/navigation.ts#L377-L410)).
