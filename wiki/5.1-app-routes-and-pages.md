## Overview

`packages/web/src/app` is a Next.js 16 App Router tree of 54 page routes, one Route Handler, and 20 layouts, in 77 non-test source files and roughly 16,500 lines (counted with `find` and `wc -l`; nine colocated test files are excluded). It is a client-first application: 51 of the 54 pages carry `'use client'`, and most of them read the gateway's REST API through TanStack Query hooks. The three exceptions are the two docs pages, which read Markdown off the filesystem at build time, and a one-line redirect.

Server rendering is used for exactly one job besides docs: authorization. None of the 20 layouts carries `'use client'`, and the 19 nested ones each await a session check before rendering their subtree, so a role gate runs on the server and cannot be defeated by editing client state.

Every page except six opens with the shared `PageHeader` primitive (a mono "chapter" eyebrow such as `§ Govern`, a title, an optional subtitle and an actions slot), which is the one header convention across the tree. The exceptions are the three sign-in pages (login, reset password, and the OAuth consent screen, which each draw their own panel instead), the redirect, the run viewer (which draws its own full-height header), and the single doc page (which draws a breadcrumb) [packages/web/src/components/ui/PageHeader.tsx#L3-L39](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/ui/PageHeader.tsx#L3-L39).

Page titles come from one list. `lib/navigation.ts` declares every sidebar entry with its label, icon and minimum role, and the same labels feed the top bar title and the H1 of pages reachable from the sidebar, so the three cannot drift apart [packages/web/src/lib/navigation.ts#L4-L19](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/navigation.ts#L4-L19).

There are no route groups, no `loading.tsx`, no `error.tsx`, no `global-error.tsx`, and no `not-found.tsx` anywhere in the tree. Loading and error states are rendered inline by each page from its query state, usually through the shared `QueryBoundary` or `LoadingState` components, and uncaught render errors are caught by a single `ErrorBoundary` wrapped around the whole app in the root layout [packages/web/src/app/layout.tsx#L61-L63](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/layout.tsx#L61-L63). The root layout is also marked `force-dynamic`, because it injects the browser-facing API and Temporal UI URLs from the running container's environment [packages/web/src/app/layout.tsx#L28-L33](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/layout.tsx#L28-L33).

### Shell, home, and authentication

| URL | File | Kind | Shows |
| --- | ---- | ---- | ----- |
| `/` | `app/page.tsx` | client | Dashboard home, built from the work-request list (`GET /api/v1/workflows`): status and volume charts, an approvals inbox widget, recent outcomes, and the new-request and run-template modals. A deployment with no work requests shows the onboarding panel instead |
| `/login` | `app/login/page.tsx` | client | Email/password and magic-link tabs plus GitHub, Google, and Okta buttons, shown only for the providers a probe of `/api/v1/auth/providers` reports |
| `/reset-password` | `app/reset-password/page.tsx` | client | Token-driven password reset, reading `?token=` inside a `Suspense` boundary |
| `/oauth/consent` | `app/oauth/consent/page.tsx` | client | The approval screen an MCP client sends the user to: who is asking, where the result goes, what it may do, Approve or Deny |
| `/settings` | `app/settings/page.tsx` | client | Five numbered sections: profile, linked sign-in accounts, credentials, personal API tokens, and connected apps |
| `/health` | `app/health/route.ts` | Route Handler | `{ "status": "ok" }` for the container `HEALTHCHECK` |
| `/lessons` | `app/lessons/page.tsx` | server | Redirect to `/govern/lessons` |

`login`, `reset-password`, and `oauth/consent` all need `useSearchParams`, which requires a `Suspense` boundary above it for static prerender, so each wraps its real body in an inner component [packages/web/src/app/reset-password/page.tsx#L13-L20](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/reset-password/page.tsx#L13-L20). Only `/login` and `/reset-password` are chromeless: `AppShell` renders them without the sidebar or top bar [packages/web/src/components/layout/AppShell.tsx#L9-L31](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/layout/AppShell.tsx#L9-L31).

The login page learns which sign-in methods exist by probing the gateway rather than from build-time configuration. It renders a social button only when the probe reports that provider, and treats a 200 that does not match the expected shape as a gateway that is not really there [packages/web/src/app/login/page.tsx#L182-L210](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/login/page.tsx#L182-L210).

**The consent screen** is the dashboard half of the MCP authorization flow described in [MCP Server and OAuth](./3.5-mcp-server-and-oauth.md). The proxy lets it through without a session marker, because the browser can arrive straight from the authorization server before this app has set one; the page therefore calls `hydrateFromSession` itself and shows a sign-in prompt, a retry, or the decision form depending on the probe result [packages/web/src/components/oauth/ConsentScreen.tsx#L32-L82](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/oauth/ConsentScreen.tsx#L32-L82). The decision form shows the app's self-chosen name behind an `unverified` badge, the host of the redirect URI it will be sent to, a warning when that host is local, and the scopes requested. Read is described when the request carries a read or write scope; Write appears as an unchecked box only when the request asked for `mcp:write` and the operator allows write tools, and the write scope is granted only if that box is checked [packages/web/src/components/oauth/ConsentScreen.tsx#L84-L132](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/oauth/ConsentScreen.tsx#L84-L132). Its two calls go to the authorization server's own `/api/auth/oauth2/public-client` and `/api/auth/oauth2/consent` endpoints with the session cookie, not through the bearer-token API client, and the consent answer is the URL the browser is then sent to [packages/web/src/hooks/useOAuthConsent.ts#L9-L53](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/hooks/useOAuthConsent.ts#L9-L53). Apps a user has approved are listed in the fifth Settings section, which reads `GET /api/v1/me/mcp-grants`, offers one Disconnect action per app, and hides itself when MCP is off and nothing is connected [packages/web/src/components/settings/ConnectedAppsSection.tsx#L22-L45](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/settings/ConnectedAppsSection.tsx#L22-L45) [packages/web/src/hooks/useMcpGrants.ts#L22-L37](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/hooks/useMcpGrants.ts#L22-L37). See [`docs/mcp-server.md`](https://github.com/yorch/auto-swe/blob/ae416937/docs/mcp-server.md) for the server side.

The hook turns its filter object into query parameters (`status`, `templateId`, `templateVersion`, `scope`, `includeChannel`, `limit`, `offset`), so filtering and paging happen at the gateway and each filter change resets the offset to the first page [packages/web/src/hooks/useRuns.ts#L212-L252](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/hooks/useRuns.ts#L212-L252) [packages/web/src/app/runs/page.tsx#L23-L91](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/runs/page.tsx#L23-L91). The epic detail page holds a 45-second startup grace window: the epic's row only appears after the orchestrator's first state update, so a 404 inside that window renders "epic is starting" rather than an error [packages/web/src/app/epics/[workflowId]/page.tsx#L25-L60](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/epics/%5BworkflowId%5D/page.tsx#L25-L60).

The editor route is the second-largest page in the tree at 1,117 lines. ## Layouts, gating, and dynamic segments

Three mechanisms guard a route, in order. The proxy runs first and only checks for the presence of one of two session cookies, redirecting to `/login?redirect=<path>` when neither is set; `/login`, `/api`, `/reset-password`, `/health`, and `/oauth/consent` are exempt [packages/web/src/proxy.ts#L14](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/proxy.ts#L14) [packages/web/src/proxy.ts#L52-L67](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/proxy.ts#L52-L67). It also forwards the matched pathname and query string to Server Components in headers, since layouts cannot read the URL, and it sets `frame-ancestors 'none'` and `X-Frame-Options: DENY` on `/login` and `/oauth/consent`, the two pages that take a credential or a security decision [packages/web/src/proxy.ts#L17-L50](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/proxy.ts#L17-L50).

Next, each nested `layout.tsx` calls `RoleLayout`, which awaits `requireRole`. That function runs `checkSession`, a server-side `GET /api/v1/auth/me` with the cookie's bearer token, and then decides by outcome [packages/web/src/lib/auth.server.ts#L34-L77](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/auth.server.ts#L34-L77):

| Outcome of the check | Result |
| --- | --- |
| No bearer, or the gateway answers 401 | Redirect to `/login` carrying the original path; when the session marker cookie is present the redirect also asks the login page to re-mint the bearer from the longer-lived session and return |
| The gateway answers 403, the user is inactive, or no allowed role is met under the shared `roleMeets` hierarchy | Redirect to `/` |
| The gateway is unreachable or answers something else | `RoleLayout` renders an error alert rather than treating an outage as "not allowed" |

[packages/web/src/lib/auth.server.ts#L80-L127](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/auth.server.ts#L80-L127) [packages/web/src/components/auth/RoleLayout.tsx#L10-L23](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/auth/RoleLayout.tsx#L10-L23). The gateway's own RBAC is the third and authoritative gate on every API call. Pages outside `/govern` and `/studio` have no layout, so they get only the proxy's cookie check on the server and whatever the page itself hides.

The 19 nested layouts resolve to three tiers; `allowed` lists accepted roles and `roleMeets` admits anyone at or above any of them:

| Gate | Layouts |

| ENGINEER and above (any active user) | `govern/` |

`/runs/[id]` is the third-largest page in the tree at 998 lines, and it delegates trace rendering to two sibling modules in the same directory: `TracesTab` (702 lines) and `SplitRunPanel` (109 lines). The page ships three alternative renderings of the same run, chosen by a per-user layout preference rather than by URL. `LayoutA` is a split console pairing an execution graph (with a graph/outline switch) with a console that has a Split/Stream mode toggle; `LayoutB` is a transcript with a step spine; `LayoutC` is a flight recorder with a waterfall and an 11-second playhead animation [packages/web/src/app/runs/[id]/page.tsx#L61-L190](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/runs/%5Bid%5D/page.tsx#L61-L190) [packages/web/src/app/runs/[id]/page.tsx#L385-L396](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/runs/%5Bid%5D/page.tsx#L385-L396) [packages/web/src/app/runs/[id]/page.tsx#L925-L965](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/runs/%5Bid%5D/page.tsx#L925-L965).

**Linking traces to the graph.** Each trace carries the key of the spec node that produced it and a recording id that prefixes the fan-out branch path (`fan[0]/impl`). Selecting a graph node selects every execution of that node across all branches; selecting a step row selects exactly one branch's execution. Traces recorded without those columns fall back to the spec nodes that run the same activity and are flagged as ambiguous rather than guessed [packages/web/src/lib/traceLinkage.ts#L1-L60](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/traceLinkage.ts#L1-L60). `TracesTab` groups the selected traces by branch and prints a `Branch fan[0]` header when any trace belongs to one [packages/web/src/app/runs/[id]/TracesTab.tsx#L512-L640](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/runs/%5Bid%5D/TracesTab.tsx#L512-L640).

`TracesTab` is the shared trace renderer used by all three layouts: it labels each event by kind (llm, tool, event), summarizes tool calls and activity events such as TDD test runs and PR creation, caps oversized payloads, shows token and cost chips, and links each LLM-response trace that has an OpenTelemetry trace id to the Tempo explorer in Grafana [packages/web/src/app/runs/[id]/TracesTab.tsx#L12-L80](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/runs/%5Bid%5D/TracesTab.tsx#L12-L80) [packages/web/src/app/runs/[id]/TracesTab.tsx#L125-L165](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/runs/%5Bid%5D/TracesTab.tsx#L125-L165) [packages/web/src/app/runs/[id]/TracesTab.tsx#L320-L366](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/runs/%5Bid%5D/TracesTab.tsx#L320-L366).

**Live updates.** The page loads the run through `useRunDetail`. The first read requests `GET /api/v1/workflow-runs/:id?includeTraces=true`. Each poll after that reads the run without traces and only the traces created since a cursor, `GET /api/v1/workflow-runs/:id/traces?since=`, and appends them to the cached run; the cursor trails the last read by 10 seconds because a trace's timestamp is the writer's clock, not its commit time. The poll falls back to a full read when the merged count disagrees with the server's total and once when the run turns terminal. ## The docs surface

`/docs` and `/docs/[slug]` publish the repository's living documentation inside the dashboard, and they are the only routes that opt into static generation explicitly. Both set `dynamic = 'force-static'`; the slug route adds `dynamicParams = false` and enumerates its pages from `generateStaticParams`, so the served set is frozen at build time and any other slug 404s [packages/web/src/app/docs/[slug]/page.tsx#L9-L15](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/docs/%5Bslug%5D/page.tsx#L9-L15).

`listDocs` reads `../../docs` relative to the package, keeps only top-level `.md` files whose basename matches `/^[a-z0-9][a-z0-9-]*$/i`, and derives each title from the file's own `# heading` with the first non-heading paragraph as a 140-character description. Only `README` carries a title override (`Overview`), and the comment on that map warns that an entry there silently outlives the file it describes. Serving only the top level is deliberate: `docs/history/` is frozen and publishing it would advertise superseded behaviour as current [packages/web/src/lib/docs.ts#L15-L67](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/docs.ts#L15-L67). The container image copies only `docs/*.md` for the same reason [packages/web/Dockerfile#L53-L58](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/Dockerfile#L53-L58).

The non-obvious part is link rewriting. The docs are authored to be read as files, so a cross-reference is written as a markdown link whose target is the bare filename `./agents.md`. Rendered at `/docs/architecture`, that href resolves against the URL and becomes `/docs/agents.md` — which the route rejects, since the slug pattern has no dot and `dynamicParams` is off. Every cross-doc link would 404. `resolveDocLink` classifies each href into one of three outcomes before rendering [packages/web/src/lib/docLinks.ts#L73-L124](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/docLinks.ts#L73-L124).

| Href shape | Resolution | Rendered as |
| --- | --- | --- |
| `http:`, `https:`, `mailto:` | `href` | `<a target="_blank" rel="noopener noreferrer">` |
| `#section` | `href` | Anchor, unchanged |
| `/studio/models` | `href` | Dashboard route, unchanged |
| `./agents.md#3-6` | `doc` | `<Link href="/docs/agents#3-6">` |
| `./slack-app-manifest.json` | `unserved` — not a Markdown document | Plain text with a tooltip |
| `../AGENTS.md` | `unserved` — outside the docs directory | Plain text with a tooltip |
| `./history/evals-rfc.md` | `unserved` — not published to the dashboard | Plain text with a tooltip |
| `./nonexistent.md` | `unserved` — no such doc page | Plain text with a tooltip |

Relative paths are normalized by `resolveWithinDocs`, a string-only walker that drops `.` segments, pops on `..`, and returns null the moment a `..` would escape `docs/` — no filesystem access, so it is safe to run during static generation [packages/web/src/lib/docLinks.ts#L43-L65](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/docLinks.ts#L43-L65). A protocol-relative `//host` href is treated as unserved rather than passed through, because it inherits the page's scheme and can point anywhere, and the same check keeps `javascript:` hrefs out of the DOM [packages/web/src/lib/docLinks.ts#L78-L98](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/docLinks.ts#L78-L98).

The page component passes `servedDocSlugs()` into `Markdown`, which installs a custom anchor renderer only when that set is supplied — without it, relative links are left exactly as authored [packages/web/src/components/docs/Markdown.tsx#L16-L47](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/docs/Markdown.tsx#L16-L47) [packages/web/src/components/docs/Markdown.tsx#L112-L117](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/docs/Markdown.tsx#L112-L117). A degraded link renders as dotted-underlined text whose tooltip names the reason and says the target lives in the repository, on the stated principle that a link that goes nowhere is worse than prose. The renderer also intercepts fenced code: a ```` ```mermaid ```` block is prefixed with a line saying it is diagram source, because no Mermaid renderer is installed in the dashboard [packages/web/src/components/docs/Markdown.tsx#L50-L72](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/docs/Markdown.tsx#L50-L72).

**Relation to the public site.** The `site` workspace publishes the same documents as a second surface. Its `syncDocs.mjs` reads the same top-level `docs/*.md` files with the same slug rule so that the two surfaces publish the same set, copies them into a generated, gitignored content collection at build time, and adds the root README and the CLI README as extra pages [site/scripts/syncDocs.mjs#L1-L24](https://github.com/yorch/auto-swe/blob/ae416937/site/scripts/syncDocs.mjs#L1-L24) [site/scripts/syncDocs.mjs#L52-L58](https://github.com/yorch/auto-swe/blob/ae416937/site/scripts/syncDocs.mjs#L52-L58) [site/scripts/syncDocs.mjs#L143-L161](https://github.com/yorch/auto-swe/blob/ae416937/site/scripts/syncDocs.mjs#L143-L161). Neither surface owns the content, and they solve relative links differently: the dashboard degrades an unserved target to plain text, while the site resolves it to the file on GitHub, since a reader of the public site is already outside the product [site/scripts/docLinks.mjs#L1-L30](https://github.com/yorch/auto-swe/blob/ae416937/site/scripts/docLinks.mjs#L1-L30). The site also renders Mermaid diagrams, which the dashboard does not.

## Limitations

- **`/epics` and `/epics/[workflowId]` have no navigation item.** `NAV_GROUPS` lists neither, the sidebar defines an `epics` icon that no item uses, and `/epics` appears only in the page-title table for pages without a sidebar entry. The list links to each epic and the create modal navigates to the new one, so the only inbound links come from the epic pages themselves; a user reaches them by typing the URL [packages/web/src/lib/navigation.ts#L163-L173](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/lib/navigation.ts#L163-L173) [packages/web/src/components/layout/Sidebar.tsx#L22-L23](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/layout/Sidebar.tsx#L22-L23) [packages/web/src/app/epics/page.tsx#L124-L130](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/epics/page.tsx#L124-L130).
- **`/docs` is linked only from the first-run onboarding panel.** It has no sidebar entry, and the panel that links to it renders only when the deployment has no work requests at all, so an established deployment reaches the in-app docs by typing the URL [packages/web/src/app/page.tsx#L131-L137](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/app/page.tsx#L131-L137) [packages/web/src/components/dashboard/DashboardOnboarding.tsx#L178-L184](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/dashboard/DashboardOnboarding.tsx#L178-L184).
- **`/oauth/consent` renders inside the app chrome.** The proxy treats the page as public, but `AppShell` lists only `/login` and `/reset-password` as chromeless, so the consent screen, including its signed-out branch, is drawn inside the sidebar and top bar, whose queries, by the shell's own comment, would 401 for a signed-out visitor [packages/web/src/components/layout/AppShell.tsx#L9-L31](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/components/layout/AppShell.tsx#L9-L31) [packages/web/src/proxy.ts#L9-L14](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/proxy.ts#L9-L14).
- **Pages outside `/govern` and `/studio` have no server-side role check.** They are guarded by the proxy's cookie-presence test and by what each page hides from a lower role; the gateway still refuses the API calls, but the page shell renders for any signed-in browser [packages/web/src/proxy.ts#L59-L66](https://github.com/yorch/auto-swe/blob/ae416937/packages/web/src/proxy.ts#L59-L66).
- **There is no route-level error or loading UI.** With no `error.tsx` or `loading.tsx` anywhere, a page that throws during render falls all the way to the single app-wide `ErrorBoundary`, losing the surrounding chrome context that a nested boundary would have preserved.
- **Docs are frozen at build time.** `force-static` plus `dynamicParams = false` means a documentation file added or edited after the image is built is invisible until the next build.
- **Mermaid diagrams in docs are not rendered**, only labelled as diagram source, because adding the renderer to the dashboard is a dependency decision that has not been taken; the public site renders them.
