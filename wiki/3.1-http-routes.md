## Overview

The gateway's HTTP surface is a set of Fastify plugin modules under `packages/gateway/src/routes/`, each exporting a `FastifyPluginAsync` (for example `workRequestRoutes`) that [`index.ts`](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts) registers under a URL prefix. Counted as non-test `.ts` files in `routes/`, there are 50 route modules. A grep for `app.<verb>` / `fastify.<verb>` call sites (`get`, `post`, `put`, `patch`, `delete`) in those files finds about 243 handler registrations. That count is approximate: it matches call-site text, so a handler registered through a helper is missed.

Modules share one conventions layer: Zod validation, a uniform error envelope, per-route `requireAuth` guards, and query filters that scope list results to what the caller may see. Authentication itself and role semantics are covered on the sibling authentication page.

## Implementation

### Bootstrap and global behaviour

`start()` in `index.ts` creates the Fastify app and installs `validatorCompiler` and `serializerCompiler` from `fastify-type-provider-zod`, so every route schema is a Zod schema ([index.ts:L108-L110](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L108-L110)). An `onRoute` hook gives any route without a response schema a permissive `z.any()` for 200 responses, which prevents fast-json-stringify from silently stripping undeclared fields ([index.ts:L112-L117](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L112-L117)). CORS, raw-body capture (opt-in per route, for webhook HMAC verification), cookies and a global rate limit of 200 requests per minute follow, keyed by `rateLimitKey` ([index.ts:L121-L145](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L121-L145)).

The global error handler returns `{ error: { code, message } }`. Messages on 4xx pass through, while 5xx responses are replaced with "Internal server error" so database or library text does not leak ([index.ts:L209-L221](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L209-L221)). Route code returns the same envelope for its own refusals, as in the inactive-user 403 on `/api/v1/me`.

### Registration order and route families

Registration order in `index.ts` is meaningful. The `/health` handler is declared first ([index.ts:L224](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L224)). The OAuth gate (`mcpOAuthGate`) and consent audit are registered before the better-auth routes because the gate's hooks apply only to routes registered after it ([index.ts:L231-L235](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L231-L235)). The MCP bridge plugin goes on the root before `mcpRoutes`, since `requireAuth` on every route consults it ([index.ts:L237-L243](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L237-L243)). Inline handlers for `/api/v1/auth/providers` and the session-token bridge `/api/v1/auth/session-token` live in `index.ts` itself ([index.ts:L253](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L253)).

Everything else is registered with a prefix, in three families ([index.ts:L309-L395](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L309-L395)):

| Family | Prefix | Examples |
| ------ | ------ | -------- |
| Self-service and work | `/api/v1/<resource>` | `work-requests`, `agent-runs`, `workflow-runs`, `workflow-templates`, `pull-requests`, `tickets`, `epics`, `prd-runs`, `lessons`, `human-steps`, `me`, `users`, `teams` |
| Repository sub-resources | `/api/v1/repositories` | `repositoryRoutes`, `repoDependencyRoutes` and `connectionCredentialRoutes` all share this prefix |
| Platform administration | `/api/v1/platform` | `adminRoutes`, `modelConfigRoutes`, `systemConfigRoutes`, `scannerPatternRoutes`, `configSettingsRoutes`, `githubInstallationRoutes`, `bundleRoutes`, `usageRoutes`, `readinessRoutes`, `skillsRoutes`, `evalRoutes` |

Several platform modules are registered a second time under the deprecated `/api/v1/admin` prefix, each marked "Deprecated alias" in comments ([index.ts:L321-L322](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L321-L322)). The human-step routes likewise answer on both `/api/v1/human-steps` and the legacy `/api/v1/inbox` ([index.ts:L393-L395](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/index.ts#L393-L395)). Some platform modules (for example `githubWebhookSecretRoutes`, `githubHostCredentialRoutes`, `skillSourceRoutes`) have no alias and exist only under `/platform`. Team-scoped agent and skill modules (`teamAgentSkillRoutes`, `teamAgentLibraryRoutes`) mount under `/api/v1/teams`.

### Route module shape and guards

A module typically opens with `fastify.withTypeProvider<ZodTypeProvider>()` and declares each handler with an options object holding `onRequest: requireAuth({ requiredRole })`, optionally `config: { mcpScope: 'read' | 'write' }`, and a `schema` with `querystring`, `params` or `body` ([workRequests.ts:L314-L324](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/routes/workRequests.ts#L314-L324)). Handlers call `requireUser(request)` to get the authenticated actor. Role floors are declared per route: `admin.ts` uses `requiredRole: 'ADMIN'` ([admin.ts:L117](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/routes/admin.ts#L117)), and `teams.ts` mixes `ADMIN`, `ENGINEER` and `LEAD` floors with a team-scoped check (`requiredTeamRole`, `teamIdParam`) ([teams.ts:L316](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/routes/teams.ts#L316)).

### Visibility filtering

List and read routes do not rely on the role check alone; they build a Prisma `where` that limits rows to what the actor may reach. In the work-request list, an `ADMIN` gets no extra filter, and everyone else is restricted to requests with an active workflow on a repository matching `reachableConnections(user, request.repoAccessGate)` ([workRequests.ts:L328-L340](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/routes/workRequests.ts#L328-L340)).

`reachableConnections` in `lib/tenantScope.ts` ANDs team membership (owning or shared team) with the GitHub permission requirement, so a permission row can only remove access ([tenantScope.ts:L99-L114](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/lib/tenantScope.ts#L99-L114)). Its `gate` argument is required but may be `undefined`, so a caller must state that it passes no gate ([tenantScope.ts:L57-L76](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/lib/tenantScope.ts#L57-L76)). Workflow-run routes use `buildWorkflowRunVisibilityFilter(user, request.repoAccessGate)`, which returns `{}` for admins and an `OR` of conditions otherwise; a requester keeps seeing runs they launched after leaving the team ([runVisibility.ts:L55-L70](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/lib/runVisibility.ts#L55-L70), applied at [workflowRuns.ts:L250](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/routes/workflowRuns.ts#L250)). Those helpers are documented in depth with repository access.

### Boolean query parameters

`booleanQueryParam(defaultValue = false)` is a Zod `enum(['true','false'])` made optional and transformed to a real `boolean`, using the default when the parameter is omitted ([queryParams.ts:L26-L29](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/lib/queryParams.ts#L26-L29)). It exists because `z.coerce.boolean()` is `Boolean(input)`, which turns the string `"false"` into `true`. Any other spelling (`1`, `0`, mixed case, a bare `?flag`) fails querystring validation with a 400 ([queryParams.ts:L3-L24](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/lib/queryParams.ts#L3-L24)). It is used in routes such as `workflowRuns.ts`, e.g. `fullTraces: booleanQueryParam(false)` and `includeSpec: booleanQueryParam(true)` ([workflowRuns.ts:L39-L45](https://github.com/yorch/auto-swe/blob/d0a90fb5/packages/gateway/src/routes/workflowRuns.ts#L39-L45)).
